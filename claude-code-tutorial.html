01

설치하기

운영체제에 맞는 한 줄 명령으로 설치합니다.

bash
curl -fsSL https://claude.ai/install.sh | bash
PowerShell
irm https://claude.ai/install.ps1 | iex
Node.js 18 이상
npm install -g @anthropic-ai/claude-code

설치가 끝나면 버전을 확인하고, 처음 실행할 때 브라우저로 로그인합니다. Claude 구독(Pro·Max·Team·Enterprise) 계정이나 Anthropic Console의 API 계정 중 하나로 로그인할 수 있습니다.

확인
claude --version
claude doctor   # 설치 상태 점검
Windows 팁. Claude Code는 Windows에서 Git Bash를 사용해 셸 명령을 실행합니다. Git for Windows가 설치되어 있는지 먼저 확인하세요. WSL 안에서 Linux 방식으로 설치해도 됩니다.
02

첫 세션 시작

프로젝트 폴더에서 claude를 실행하면 대화형 세션이 열립니다.

bash
cd my-project
claude                         # 대화형 세션 시작
claude "이 프로젝트 구조를 설명해줘"   # 첫 질문과 함께 시작
claude -c                      # 가장 최근 대화 이어가기
claude -r                      # 이전 대화 목록에서 골라 재개

처음 열었다면 코드베이스에 대해 질문하는 것부터 해 보세요. Claude는 필요한 파일을 직접 찾아 읽습니다. 어떤 파일을 봐야 하는지 미리 알려줄 필요는 없습니다.

  • “이 프로젝트는 무슨 일을 해? 진입점이 어디야?”
  • “로그인 흐름이 어떤 파일들을 거치는지 따라가 줘.”
  • “테스트는 어떻게 실행해?”
03

프롬프트 잘 쓰기

구체적일수록 한 번에 끝납니다.

모호한 요청“버그 고쳐줘”
구체적인 요청“빈 장바구니로 결제하면 500 에러가 나. 재현 테스트를 먼저 쓰고, 고친 뒤 테스트가 통과하는지 확인해줘.”

도움이 되는 습관

  • 파일 참조: @src/auth.ts처럼 @로 파일이나 폴더를 직접 지정합니다.
  • 이미지: 스크린샷을 터미널에 붙여 넣거나 드래그해서 UI 버그나 디자인 시안을 보여줄 수 있습니다.
  • 검증 기준: “테스트 통과”, “빌드 성공”, “린트 경고 없음”처럼 완료 조건을 알려주면 Claude가 스스로 확인합니다.
  • 큰 작업은 계획부터: 여러 파일을 바꾸는 작업은 플랜 모드(레슨 04)에서 계획을 먼저 확인합니다.
  • 중간에 방향 바꾸기: 작업 중에도 메시지를 보낼 수 있고, Esc로 멈춘 뒤 다시 지시할 수 있습니다.
04

권한 모드

Claude가 어디까지 묻지 않고 실행할지 정합니다. Shift+Tab으로 전환합니다.

모드동작언제 쓰나
기본파일 수정과 명령 실행 전에 매번 허락을 구합니다.처음 쓸 때, 낯선 저장소
편집 자동 수락파일 수정은 바로 적용하고, 셸 명령은 여전히 묻습니다.방향이 확실한 구현 작업
플랜 모드읽기와 조사만 하고 계획을 제시합니다. 승인 전에는 아무것도 바꾸지 않습니다.리팩터링, 설계 검토
자동 모드안전하다고 판단한 작업은 묻지 않고 진행합니다(계정에 따라 제공).길고 반복적인 작업

자주 쓰는 명령은 /permissions에서 허용 목록에 추가하면 매번 묻지 않습니다. 설정은 프로젝트의 .claude/settings.json에 저장되어 팀과 공유할 수 있습니다.

.claude/settings.json
{
  "permissions": {
    "allow": ["Bash(npm run test:*)", "Bash(git status)"],
    "deny":  ["Read(./.env)"]
  }
}
05

CLAUDE.md와 메모리

세션이 바뀌어도 Claude가 기억해야 할 프로젝트 지식을 적어 둡니다.

CLAUDE.md는 세션이 시작될 때마다 자동으로 읽히는 안내서입니다. /init을 실행하면 Claude가 코드베이스를 분석해 초안을 만들어 줍니다.

위치범위
~/.claude/CLAUDE.md내 모든 프로젝트에 적용되는 개인 규칙
./CLAUDE.md이 저장소의 팀 공용 규칙. git에 커밋합니다.
./CLAUDE.local.md이 저장소에서 나만 쓰는 메모. git에서 제외합니다.
하위 폴더의 CLAUDE.md그 폴더의 파일을 다룰 때 추가로 읽힙니다.

무엇을 적을까

CLAUDE.md 예시
# CLAUDE.md

## 명령
- 개발 서버: pnpm dev
- 단일 테스트: pnpm vitest run src/cart.test.ts

## 구조
- API 라우트는 app/api/, DB 접근은 반드시 lib/db.ts를 거친다

## 규칙
- 새 의존성을 추가하기 전에 먼저 물어볼 것

짧고 구체적으로 유지하세요. 코드만 봐도 알 수 있는 내용보다, 여러 파일을 읽어야 알 수 있는 구조와 팀의 암묵적인 규칙이 가치가 큽니다. 세션 중에 “앞으로 커밋 메시지는 한국어로 써줘. 기억해 둬”처럼 말하면 Claude가 메모리에 저장해 다음 세션에서도 따릅니다.

06

슬래시 명령과 단축키

입력창에서 /를 누르면 전체 목록이 나타납니다.

명령하는 일
/help도움말과 명령 목록
/init코드베이스를 분석해 CLAUDE.md 생성
/model사용할 모델 변경
/clear대화 기록을 비우고 새로 시작
/compact대화를 요약해 컨텍스트 공간 확보
/context컨텍스트 사용량 확인
/resume이전 대화로 돌아가기
/permissions허용·거부 규칙 관리
/config테마 등 설정 변경
/code-review현재 변경 사항의 버그 검토
단축키하는 일
Esc진행 중인 작업 멈추기
Esc Esc이전 메시지로 되감기(코드 변경도 되돌릴 수 있음)
Shift+Tab권한 모드 전환
@파일·폴더 참조
!셸 명령을 직접 실행하고 결과를 대화에 넣기
Ctrl+C입력 취소, 두 번 누르면 종료
07

컨텍스트 관리

대화가 길어질수록 관련 없는 내용이 쌓입니다.

  • 작업이 바뀌면 /clear. 버그 수정이 끝나고 새 기능을 시작한다면 새 대화가 더 정확합니다.
  • 이어가야 하면 /compact. 핵심만 남기고 요약합니다. /compact 인증 관련 결정만 남겨줘처럼 무엇을 남길지 지정할 수 있습니다.
  • /context로 확인. 시스템 프롬프트, 도구, 메시지가 각각 얼마나 차지하는지 보여줍니다.
  • 넓은 탐색은 서브에이전트에게. 많은 파일을 뒤지는 조사는 별도 에이전트가 하고 결론만 돌려주므로 메인 대화가 가벼워집니다.
08

Git 워크플로

브랜치, 커밋, PR까지 대화로 처리합니다.

대화 예시
> feature/cart-fix 브랜치를 만들고 지금 변경을 커밋해줘
> 변경 내용을 요약해서 PR을 열어줘
> PR #42의 리뷰 코멘트를 반영해줘
> main과 충돌난 부분을 해결해줘

GitHub 작업에는 gh CLI가 설치·로그인되어 있어야 합니다. 여러 작업을 동시에 진행하려면 git worktree로 폴더를 나누고 각 폴더에서 별도의 Claude 세션을 실행하세요. 서로의 변경이 섞이지 않습니다.

안전 장치. Claude는 요청받지 않으면 커밋하거나 푸시하지 않습니다. git push --force처럼 되돌리기 어려운 명령은 실행 전에 확인을 구합니다.
09

스킬·서브에이전트·훅

반복하는 일을 Claude Code에 가르치는 세 가지 방법입니다.

스킬특정 작업의 절차를 담은 지침서. .claude/skills/이름/SKILL.md에 두면 관련 작업에서 자동으로 불러오고, /이름으로 직접 호출할 수도 있습니다.
서브에이전트자기 컨텍스트와 도구를 가진 전문 보조. .claude/agents/*.md에 정의하거나 /agents로 만듭니다.
훅특정 시점에 반드시 실행되는 셸 명령. Claude의 판단이 아니라 하네스가 실행하므로 항상 지켜집니다.

스킬 예시

.claude/skills/release-notes/SKILL.md
---
name: release-notes
description: 지난 태그 이후 커밋으로 한국어 릴리스 노트를 작성한다
---

1. git describe --tags --abbrev=0 으로 마지막 태그를 찾는다
2. 그 이후 커밋을 기능 / 수정 / 기타로 분류한다
3. CHANGELOG.md 맨 위에 새 섹션으로 추가한다

훅 예시: 파일 수정 후 자동 포맷

.claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "type": "command", "command": "npx prettier --write ." }]
    }]
  }
}

그 밖의 훅 시점으로는 PreToolUse(도구 실행 전 차단 가능), UserPromptSubmit, Stop, SessionStart, Notification 등이 있습니다. 직접 JSON을 쓰기 어렵다면 “파일을 고칠 때마다 prettier를 돌리게 설정해줘”라고 부탁하세요.

10

MCP와 자동화

외부 도구를 연결하고, 사람 없이 Claude를 실행합니다.

MCP(Model Context Protocol) 서버를 연결하면 Claude가 이슈 트래커, 데이터베이스, 브라우저, 디자인 도구 같은 외부 시스템을 직접 사용할 수 있습니다.

bash
claude mcp add --transport http 이름 https://example.com/mcp
claude mcp list          # 연결된 서버 확인
# 세션 안에서는 /mcp 로 상태 확인·인증

-p 옵션을 쓰면 대화 없이 한 번 실행하고 결과만 출력합니다. 스크립트, 파이프, CI에서 활용할 수 있습니다.

헤드리스 실행
claude -p "src/의 TODO 주석을 표로 정리해줘"
cat error.log | claude -p "이 에러의 원인을 한 문단으로 설명해줘"
claude -p "변경 사항을 리뷰해줘" --output-format json

정해진 시간마다 작업을 돌리고 싶다면 /schedule로 클라우드 예약 작업을, 세션 안에서 반복하려면 /loop 5m /명령을 사용할 수 있습니다.

다음 단계: 실제 프로젝트에서 /init을 실행하고, 작은 버그 하나를 Claude와 함께 고쳐 보세요. 더 자세한 내용은 공식 문서 docs.claude.com 의 Claude Code 섹션을 참고하세요. 명령과 옵션은 버전에 따라 달라질 수 있으니 /help와 claude --help로 확인하세요.
